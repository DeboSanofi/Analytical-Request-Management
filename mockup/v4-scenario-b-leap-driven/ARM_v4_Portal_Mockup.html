How the pieces work together (TO-BE)

  1. 1 Request: the chemist raises the study request in ChemDiary; it goes to Lab Automation (LEAP). No Analytical Experiment is created in ChemDiary.
  2. 2 Worklists: LEAP creates worklists and sends them to the instruments in their formats (10p, txt, spl).
  3. 3 Files: the instruments write result files (XLS/TXT, PS, RPT) into the Lab Data Inventory; processed files such as JDX and PDF are stored alongside.
  4. 4 Read: LEAP reads the files and results from LDI.
  5. 5 Results: LEAP registers results and attachments in ChemDiary automatically.
  6. 6 Status: LEAP sends status updates to ARM, which shows them in the Requests grid and the dashboard.
Open points: what the pink "assistant" icon next to the LDI catalog is; the meaning of the 10p, txt and spl formats; and whether ARM keeps its own request ID or only mirrors LEAP and ChemDiary IDs.

Glossary NEW

TermDefinition (proposed, to be agreed)
RequestContainer for all analyses ordered for one batch in ChemDiary.
MethodOne analytical technique within a request, run on one instrument.
Task Count (dashboard)Number of methods started in the period. A task with LCMS and NMR counts once per method.
LEAP / Lab AutomationMoves requests, worklists, files and results between ChemDiary, instruments and LDI, and reports status to ARM.
WorklistInstrument input file created by LEAP. Formats 10p, txt and spl are as labelled in the flow diagram; exact meaning to confirm.
LDILab Data Inventory: catalog plus AWS storage for raw data and results, read-only for users.
Status: Ready for analystRequest received by LEAP, worklist not yet sent.
Status: Worklist sentLEAP has delivered the worklist to the instrument.
Status: Data in LDIAt least one result file for the method is stored in LDI.
